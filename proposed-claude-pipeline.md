# claude proposed pipeline

Two phases. **Phase 0** hand-builds an independent, deliberately-naive **oracle** (a complete
slow interpreter) and the human-owned semantic core; it is the correctness foundation *and*
the first alpha. **Phase 1** is the automated loop that builds the production (Go-emitting)
compiler and validates every step **differentially against the oracle** — so LLM-written code
is checked against an independent implementation, never against LLM-authored expected outputs.

Serial, single worktree; `git` is the substrate; capabilities gated by *container mounts*. See
`claude-agent-plan.md` for the Phase-0 discipline, mount matrix, retry metering, artifacts, the
correctness harness (§G), and the non-determinism detector (§F).

Conventions:
- **IMMUTABLE** — produced once, then mounted `:ro`; downstream may run but never edit it.
- **HARD STOP** — requires human interaction; blocks on a `pass-*` / `fail-*` marker.
- **[METERED]** — consumes a bounded retry budget (the mutating action is counted, the
  re-check that confirms it is free). Budgets and exhaustion behaviour are in the plan.

## Phase 0 — Foundations (human-owned; precedes the automated loop)

0.1 **Type checker + semantic analysis — hand-built by the human.**
   - The highest-ambiguity, most-novel part: structural subtyping, unions/intersections,
     refinement constraints, capability/effect propagation. Built by hand, no codegen, ASTs
     fed directly — this is the deep narrow bore that proves the spec is *implementable*.
   - You find spec gaps by implementing, and you find them **here**, before anything freezes.
     Each gap becomes a `CHANGES.md` ruling + corpus sweep (the Phase-1 step-3 discipline,
     applied by hand).
   - If the spec cannot survive a real refinement-aware structural checker, **stop** — Luna
     isn't specifiable yet and no downstream automation rescues that.

0.2 **Oracle / alpha interpreter — naive, slow, obvious, end-to-end.**
   - Lex → parse → (0.1's checker) → tree-walk evaluator. Bignum-then-bound-check for overflow,
     literal semantic rules, zero optimization. Slowness is fine: it is a test instrument and
     the alpha, not the product — optimization is the *competing* implementation's job.
   - Output: a complete Luna interpreter = **alpha v0** *and* the **oracle** for all of Phase 1.

0.3 **Independence discipline (what keeps the oracle honest).**
   - A differential test has power only if the two sides fail *differently*. Tree-walk (oracle)
     vs Go-emission (product) is structurally different code, so implementation bugs are largely
     uncorrelated for free.
   - Residual risk is *shared spec-misreading*, covered by: (a) the human owns the semantic
     core, and (b) every oracle-vs-compiler disagreement is human-adjudicated — each is a
     compiler bug or a spec gap.
   - **Alpha choice:** Phase 1 **reuses** 0.1's human front-end (lex/parse/check) and builds only
     the **backend** (Go emission + runtime + incremental cache). Honest trade-off: the shared
     front-end is *not* differential-tested — acceptable because it is human-built and exercised
     by the oracle; a later independent front-end can close that gap.

## Phase 1 — Automated loop (builds the production backend)

1. **human: pick target.** Which backend slice to implement. Written as `target` in state.

2. **spec-review** → `gaps.md`. **Supplements** Phase 0's findings — triage for anything the
   hand-build didn't surface. Pass = no blocking gaps. Cannot edit specs (`:ro`).

3. **spec-reconcile** → `CHANGES.md` ruling + corpus-wide sweep. **[METERED]**
   - Ruling with rationale (incl. rejected alternative), then sweep **every** contradicting
     site across `docs/` — grep first. Re-run `spec-review` to confirm (free). Self-abort on
     contradictory/breaking edits still consumes an attempt. Budget exhausted → hard-fail to 1.

4. **spec-review-human** — HARD STOP. `pass-spec-review-human.md` or `fail-…` (→ 3).

5. **e2e-define** → `e2e/*.luna` + `e2e/expected/*`. **IMMUTABLE**
   - Programs may be hand-written or fuzzer-seeded; **expected output is generated by the
     oracle**, never hand-authored — the oracle defines "correct."
   - Comparison policy (enforced by `e2e-runner`): exact success stdout; partial (error type +
     location) on diagnostics; partial (panic type) on panics. Maps/streams have ruled order,
     sets don't exist, so a program with no undeclared effects and no concurrent multi-writer
     output is deterministic.
   - Non-determinism excluded by the four-layer detector, not discipline (plan §F).

6. **impl-plan** → `implementation-plan.md` + `slices.md`.
   - Backend slices in dependency order (emit-core → overflow/`==`/conversion lowering →
     capability threading → … → incremental cache). Serial execution walks this order.
   - Exceedingly difficult to specify → hard-fail to human.

7. **test-builder** → `tests/`. **IMMUTABLE · [METERED]**
   - (a) Unit tests tracing to **spec sections**. (b) The **correctness harness** — differential
     + metamorphic + fuzz (plan §G) — the real spine. Metamorphic relations are derived from
     Luna's invariants (overflow panics, strict `==`, no effect without capability, no shared
     mutable state); the fuzzer generates programs, the oracle grades them.

8. **TOOL: gofmt** the test code.

9. **test-review** → coverage + quality + determinism report.
   - Coverage against spec semantics incl. edge cases; metamorphic-relation completeness.
     Quality per plan §E / `quality.md`. Determinism smells per §F. Fail → 7 (metered), then
     HARD STOP. **No** "tests are impossible" escape hatch.

10. **human-review-2** — HARD STOP. Brief review of tests + harness.

11. **implement** — per backend slice, **in order**. Tests `:ro` (run, never modify).
    - **builder gate:** `go vet` + `go build` (compiles?).
    - **test-runner gate:** `go test` (behaves?).
    - **differential gate:** compiled binary vs oracle, **and** script-mode vs compiled — must
      agree (plan §G).
    - **metamorphic/fuzz gate:** a fuzz batch through both sides + the invariant relations.

12. **TOOL: lint gate** — `gofmt` + `go vet` + `golangci-lint` (incl. `forbidigo`). **Hard**;
    failure bounces to 11 without spending a reviewer token or budget.

13–15. **sec · perf · code review — TRIAGE, not assurance.** Per touched file, diff-focused,
    whole-file-gated. **[METERED as one phase]**
    - These **filter low-hanging fruit ahead of the human**; the correctness *gate* is the
      differential/metamorphic spine (step 11), never the LLM sign-off.
    - Reviewers must emit a **counterexample / failing test where possible** (runnable against
      the oracle), not prose — an unverifiable "looks risky" is worth little.
    - sec: un-vendored/excessive deps, injections, suspicious `unsafe` Go. perf: naive
      complexity, GC pressure, cache-hostile structures. code: judgment quality per §E.
    - Any fix re-triggers lint → sec+perf on touched files → code re-confirm. Shared budget;
      exhaustion carries findings into step 17.

16. **e2e-runner gate** — every `e2e/*.luna` **plus a fresh fuzz batch** through the produced
    backend, compared to the oracle per the step-5 policy; re-run the empirical stability check
    (§F layer 4). This is the "the compiler actually *is* Luna" gate.

17. **human-review-final** — HARD STOP before merging.

Benchmarks (overflow-enforcement tax, incremental-build latency, binary size) are **deferred** —
established once the backend exists, not an alpha gate.

Throughout: every step commits with a short conventional message; loop-back is a new commit,
never a history rewrite (state counters, not the tree, record "we've been here").
